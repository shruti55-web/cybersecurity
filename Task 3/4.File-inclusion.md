# File Inclusion Vulnerability — LFI and RFI (DVWA)

## 1. Introduction to File Inclusion

File Inclusion is a web application vulnerability that occurs when an application uses user-supplied input to decide which files should be loaded or included.

In PHP, developers commonly use functions such as `include()` and `require()` to load files into an application.

For example, a website may use different files for its Home, About, and Contact pages.

If the application directly accepts a filename from the user without proper validation, an attacker may manipulate the input to make the application include an unintended file.

There are two major types of File Inclusion vulnerabilities:

1. Local File Inclusion (LFI)
2. Remote File Inclusion (RFI)

## 2. Types of File Inclusion

| LFI | RFI |
|---|---|
| LFI stands for Local File Inclusion. | RFI stands for Remote File Inclusion. |
| It involves including a file from the local server. | It involves including a file from a remote server. |
| It may expose sensitive local files. | It may allow remote content or code to be included. |
| It depends on vulnerable local file handling. | In PHP, remote inclusion depends on URL inclusion support and configuration. |

## 3. Local File Inclusion (LFI)

### What Is LFI?

Local File Inclusion (LFI) is a vulnerability that occurs when a web application allows a user to control which local file is included or loaded by the server.

An attacker may manipulate a file parameter to access files outside the intended application directory.

For example, a website may use a parameter to select a page:

`http://localhost/DVWA/vulnerabilities/fi/?page=file1.php`

If the application does not properly validate the supplied filename, it may include an unintended local file.

### How LFI Works

1. A web application accepts a filename through a URL parameter.
2. The application passes that filename to a PHP file-inclusion function.
3. The application does not properly validate the supplied value.
4. An attacker manipulates the filename or path.
5. The server may include an unintended local file.
6. Depending on the file and server configuration, sensitive information may be exposed.

### What Happens Behind the Scenes?

The application receives a filename through the `page` parameter.

A vulnerable PHP implementation might look like this:

```php
<?php
$page = $_GET['page'];

include($page);
?>
```

The problem is that the application directly uses user input inside the `include()` function.

There is no validation to confirm whether the requested file is an approved application page.

As a result, the application may include an unintended local file.

### Impact of LFI

- **Sensitive Information Disclosure:** Local files may expose configuration or other sensitive information.
- **Source Code Exposure:** Application source files may become accessible under certain conditions.
- **Internal Path Disclosure:** Error messages may reveal server directory structures.
- **Possible Code Execution:** Under certain conditions, LFI combined with another weakness may lead to code execution.

## 4. Remote File Inclusion (RFI)

### What Is RFI?

Remote File Inclusion (RFI) is a vulnerability that occurs when a web application allows an external file or resource to be included from a remote server.

In PHP, this may happen when an application passes an untrusted URL to an `include()` or `require()` function and remote inclusion is enabled.

For example, a vulnerable application might accept a file location through a URL parameter and attempt to include the supplied resource.

If the application does not validate the input, an attacker may attempt to make the server include content from an external location.

### How RFI Works

1. A web application accepts a file location from the user.
2. The application passes the supplied location to a file-inclusion function.
3. The application does not properly validate the location.
4. An attacker attempts to provide an external file location.
5. If the server allows remote inclusion, it may include the external resource.
6. Depending on the content and configuration, this may result in serious security consequences.

Do not enable remote inclusion on a production server just to perform this demonstration.

### What Happens Behind the Scenes?

A vulnerable PHP implementation might look like this:

```php
<?php
$file = $_GET['page'];

include($file);
?>
```

The application accepts a file location directly from the user.

If remote inclusion is supported and enabled, an external resource may be included by the server.

### Impact of RFI

- **Remote Code Execution:** Remote PHP code may execute on the server under vulnerable configurations.
- **Server Compromise:** Successful exploitation may give an attacker significant control over the application environment.
- **Data Exposure:** Sensitive application information may be exposed.
- **Application Availability:** Malicious included content may affect application functionality or availability.

## 5. Difference Between LFI and RFI

| Basis | LFI | RFI |
|---|---|---|
| Full Form | Local File Inclusion | Remote File Inclusion |
| File Location | Local server | Remote server |
| Main Cause | Improper local file selection | Improper remote resource inclusion |
| Input | Local file path | External file location or URL |
| Configuration | Depends on local file handling | PHP remote inclusion support may be required |
| Possible Impact | File disclosure and, in some cases, code execution | May lead to remote code execution |
| Prevention | Allowlist local files and validate paths | Avoid remote inclusion and disable unnecessary URL inclusion |

## 6. Prevention of File Inclusion Vulnerabilities

File Inclusion vulnerabilities can be prevented by controlling which files an application is allowed to load.

### 1. Input Validation

Always validate user input before using it to select a file.

Do not directly pass user-controlled input to `include()` or `require()`.

### 2. Use an Allowlist

An allowlist contains the exact filenames or page identifiers that users are allowed to access.

Instead of accepting any filename, the application should select files from a predefined list.

**Vulnerable PHP Code:**

```php
<?php
$page = $_GET['page'];

include($page);
?>
```

    'home' => 'pages/home.php',

    'contact' => 'pages/contact.php'
