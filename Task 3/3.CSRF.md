# Cross-Site Request Forgery (CSRF) — DVWA

## 1. Introduction to CSRF

Cross-Site Request Forgery (CSRF) is a web application security vulnerability in which an attacker tricks an authenticated user into performing an unwanted action on a website without the user's knowledge or permission.

It occurs when a web application trusts requests sent by a user's browser without properly verifying whether the user actually intended to perform that action.

For example, imagine that a user is logged into a website. The website uses session cookies to identify the user. If the application does not implement proper CSRF protection, an attacker may trick the user's browser into sending an unwanted request using the existing authenticated session.

**Simple Example:**

1. A user logs into a website.
2. The website creates a session and stores a cookie in the browser.
3. The user visits another untrusted webpage while still logged in.
4. That webpage attempts to make the browser send an unwanted request to the original website.
5. If the website does not verify the request properly, it may perform the action using the user's authenticated session.

## 2. How CSRF Works

CSRF takes advantage of the trust a website places in the user's browser.

**Working Process:**

1. The user authenticates with a vulnerable website.
2. The browser stores the session cookie.
3. The attacker prepares a request that attempts to perform an action on that website.
4. The user is tricked into triggering that request.
5. The browser may automatically attach the website's session cookie.
6. If the server does not validate the request's authenticity, the action may be performed.

**Important:** CSRF generally requires the victim to have an active authenticated session and the application to lack effective CSRF protection.

## 3. Practical Demonstration — Password Change CSRF

### Objective

To understand how an attacker may attempt to change an authenticated user's password without the user's intention.

### Testing Environment

- Application: Damn Vulnerable Web Application (DVWA)
- Operating System: Kali Linux
- Browser: Firefox
- Vulnerability: Cross-Site Request Forgery
- DVWA Security Level: Low (for the initial demonstration)

### DVWA Location

Open DVWA in the browser:

`http://localhost/DVWA/`

Navigate to:

**DVWA → CSRF**

### Demonstration Steps

1. Log in to DVWA using your lab account.
2. Open the CSRF vulnerability page.
3. Observe the password-change form.
4. Enter a new password in the form.
5. Submit the form and observe the result.
6. Inspect the request using the browser's developer tools or an authorized local testing tool.
7. Record the request parameters and whether the application requires a CSRF token.

For the lab demonstration, use only your own DVWA account and a temporary test password.

### What Happens Behind the Scenes?

When the user submits the password-change form:

1. The browser sends a request to the DVWA server.
2. The request contains the password-change parameters.
3. The browser may automatically include the user's session cookie.
4. The server checks the user's session.
5. If the application does not verify the user's intention using an appropriate CSRF defense, an unwanted password change may be possible.

### Expected Observation

In the vulnerable configuration, the application may accept a password-change request without a CSRF token.
